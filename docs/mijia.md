# 米家局域网只读采集

Glance 直接在同一 Wi-Fi 网络读取米家设备，不需要电脑运行中转程序。
一个 8 KiB 栈的工作线程顺序采集，每轮 60 秒；UDP 请求超时 2 秒，失败最多重试一次。
每五分钟发送一次局域网发现消息，以设备 ID 匹配已授权设备的 IP。
只实现 `miIO.info`、`get_properties`、`get_prop`，没有开关、录像或其他写命令。

私有配置放在被 Git 忽略的 `data/mijia-devices.json`，格式为设备数组：

```json
[{"id":"mi_123","name":"示例插座","model":"cuco.plug.v3","ip":"192.168.1.22","did":123,"token":"<32位设备密钥>","properties":[{"key":"power_w","siid":11,"piid":2}]}]
```

最多 16 台、每台最多 10 个属性。旧协议空调伴侣使用 `legacy` 字段指定 `get_prop` 属性名。
属性 ID 必须从对应型号的 MIoT 规格取得；不是所有设备都支持统一协议。
公开构建强制嵌入空数组，个人固件含连接密钥，不能作为公开 Release 上传。
账号登录会话不嵌入固件，API、日志和 MQTT 都不返回密钥。

`GET /api/home-devices` 提供只读快照；网页 `/home` 与第四个实体屏幕页面展示状态。
失败立即清空本轮值并显示未更新，超过 150 秒的数据也标记过期。
每个设备独立保留采样时间和递增代数，避免将旧读数重复上报。
每分钟沿现有 TLS MQTT 批量发送，字段如 `mi_123_power_w`、`mi_123_online`。
这些数据使用有界 RAM 队列，断电不保证补传；体重的持久队列不受影响。
homelab 云端使用固定字段白名单，原有 7 台设备的 26 项遥测已接入时序库。
MQTT 的 broker 确认不代表新增字段已保存；接入云端历史还需更新其字段映射。
`energy_10wh` 为插座原始电量计数（0.01 kWh/单位），网页转换为 kWh，未推断统计周期。

## 扫码动态添加（2026-10-01）

从 `/home` 的「添加设备」打开 Homelab 扫码窗口；用米家 App 授权，选择设备，再返回板子输入独立设备管理口令（沿用已有口令）保存。不会下发设备控制命令。

配置以 DID 为主键追加/更新，整份校验后原子写入 NVS `mijia_config/devices_v1`。原有设备保留，最多16台、每台10属性、JSON12KB；空间不足返回507且保留原配置。写入后采集线程自动热加载并立即重新发现地址，不重启板子。每5分钟按DID更新IP，搬家后需先让板子与设备连上同一可互通局域网。

管理写接口为 POST `/api/home-devices/config`，要求 `X-Admin-Key`，拒绝跨站请求。GET `/api/home-devices` 仍不返回 token。只有一次固件升级，以后支持型号仅更新配置。初次启动无NVS配置时使用原嵌入配置作为种子。

已实测：错误口令401、跨站403、存储和热加载200；故意配置错误IP后按DID恢复；硬件重启保留配置；新增xiaomi.humidifier.600后共9台全部在线。新加湿器读取开关、湿度和滤芯剩余，真实MQTT数据已进入VM。
