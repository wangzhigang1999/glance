# 蓝牙管理

设备网页 `/bluetooth` 与 API `/api/bluetooth` 共用现有管理口令。POST 检查同源和
`X-Admin-Key`，只允许预先确认的两台设备，不向任意扫描到的设备写入。

- LP910：`53:14:01:02:10:79`，HID 输入报告通知，使用 BLE 加密配对。
- CBL1600B：`02:01:23:27:A5:4F`，FFE0 控制及确认。
- 原小米体重秤、米家时钟继续由原广播接收器处理。建立连接时会短暂暂停扫描。
- 周围广播列表最多 24 台，按键原始报告最多 20 条，事件队列容量 48。
- 启用状态、三种手势绑定保存在独立 NVS `bluetooth/config`，密钥由 Bluedroid 管理。
- 断线自动重连；当前仅支持这两台已验证地址，暂不支持任意设备接入或网页删除配对密钥。

## 绑定与控制

连接设备后等待“已就绪”，点开关/调亮/调暗的“学习按键”，然后短按目标按钮。
20 秒无输入会退出学习。学习时不发送灯控指令；完成后写入 NVS。
LP910 当前模式发的是鼠标手势，一个上/下键会同时包含点击和位移，不能把共享点击当开关。
固件收集一段完整通知，释放后静默 120 ms（未收到释放则 300 ms）后去重、排序并匹配完整特征集合。
释放后仍保留两个 60 ms 报告间隔，避免较晚的位移报告被误判成中间键。
切换翻页器模式或改变设备固件后应重新学习。

首次开灯默认 10 档，上下每次调节 10 档，范围 0–100，0 关灯。
只在收到 `DE07B60001B0ED` 后更新“已确认亮度”；超时后显示未知，不自动重放旧命令。
灯确认超时仍以 5 秒为界，但失败后重连等待缩短为 3 秒；不把缺失确认当作控制成功。
被动扫描窗口为每 100 ms 扫描 20 ms，为两个 GATT 连接与 Wi-Fi 留出无线时间。
管理页显示最近手势识别耗时（第一条报告至识别）、灯控 ACK 耗时和本次启动超时次数，
API 另保留最近灯通知原文；这些耗时不包括按键前的设备休眠唤醒。
重连后状态未知，第一次切换按开灯处理；物理按钮/其他 App 修改状态不被自动同步。
停止连接不会自动关灯。设备未就绪、正在等待确认时的新操作会返回错误，不排队补发。

`GET /api/bluetooth` 可查看最近原始报告、完整手势及绑定，便于排查“已连接但无按键”。
管理页面只在本机局域网设备上提供，没有新增公网暴露或自动开机灯光动作。

实体屏幕第四页改为灯状态页：电量估值、连接、已确认亮度、翻页器连接和米家温湿度。
电量在连接就绪后两秒查询，随后每五分钟读取一次 `DE06A400A2ED`；只接收长度19、
命令B4、校验和有效且电量不超过100的回包，读取第8字节。查询不点灯、不改亮度。
超时保留采样时间、一分钟后重试，不因电量读取失败主动断开连接；断线或数据超过十分钟
显示等待新读数。电量是设备粗粒度估值；温湿度只取米家时钟，超过十分钟显示缺测。
实体页每秒刷新快照，与传感器采样周期独立；原米家设备采集与网页 `/home` 保留。

## 构建兼容修正

esp-idf-svc 0.52.1 在 S3 的控制器初始化中使用不存在的
`esp_idf_version_least_5_5_0` 条件；IDF 5.5.3 实际生成 `esp_idf_version_at_least_5_5_0`。
因此 `connect_en` / `adv_en` 被置为 false，即使启动日志显示 CONNECT:1。
`bt_controller_fix.rs` 配合链接器 wrap，保留其他配置并从 SDK 常量恢复这两个字段。
修正前原生串口报告 `opcode=0x200d, status=0c: Cmd Disallowed`；修正后实测可连接 LP910。
升级依赖后需复核并移除此修正，不能只看编译通过。

参考：[上游同类问题 #663](https://github.com/esp-rs/esp-idf-svc/issues/663)。
GATT 通知注册上限由 5 调到 12，以容纳翻页器多个输入特征及灯；断线时注销已登记通知。
